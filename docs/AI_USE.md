# Use of AI ("SI") tools

As the NASA Space Apps rules require, this page states where and how AI was used, and what the team did.

## How AURA was built
AURA was built by **Team Orbital Five** (team lead Aarav Awasthi and two QA testers) working with an
AI coding assistant (**Claude, by Anthropic**).
The team decided *what* to build and *why*: the product, its features, its priorities and every design
choice. Claude wrote most of the source code from those decisions. The team reviewed it, tried it as
users, reported problems and asked for changes, and set up and runs all of the infrastructure.

## What the team decided and did
**Product and design**
- Defined AURA's four parts: dashboard, analysis and alerts, AI assistant, admin panel.
- Chose prediction from each astronaut's own baseline plus trends, rather than fixed limits alone.
- Set the visual direction (minimal, premium, white and gold, "human-made, not AI-looking") and the
  zero-cost rule (free tiers only).
- Required a hardware-agnostic sensor pipeline and an admin panel to manage crew, sensors and data.

**Features the team asked for**
- **Missions**, working like game servers: anyone can host one, and changes affect only that mission.
- **Wellbeing support** for loneliness and low mood, after identifying isolation as a major risk.
- **Distance from Earth and time to return**, to show what "distance from Earth" means for the crew.
- **Long-term records:** longer history, health records, backup and restore.
- Coverage of every point in NASA's challenge text and resources (five hazards, body map, routine,
  gamification, environments), after the team brought the official challenge page and resource list.

**Security and quality**
- Asked whether one user could see another's data and whether the app would satisfy a cybersecurity
  review, which led to private chats, rate limits, accounts, an activity log and the security headers.
- Asked for a full stress test of the live system.
- The QA testers and team lead tested the live app and caught real problems, e.g. the assistant failing to answer and not being
  able to explain the simulation. Both were fixed.
- Kept AI use honest: the team chose to disclose AI-generated work accurately.

**Infrastructure (set up and run by the team lead)**
- GitHub repository, Render hosting with automatic deploys, Supabase database, Google Gemini API key
  (rotated for security), and the cron-job.org keep-alive job.

## Where AI was used
| Area | AI use |
|---|---|
| Source code | Mostly generated by Claude from the team's specifications, then reviewed and tested with the team |
| In the product | The AURA Assistant calls the Google Gemini API at runtime. Its answers are AI-generated and labelled as decision support, not medical diagnosis. |
| Text | AI helped draft the README, these documents and parts of the submission text |
| Images, video, audio | Any AI-generated image, video or voice-over in our demo carries a visible "AI-generated" label. No NASA logos, flags or mission identifiers were generated or modified. |

Every commit made with the assistant is marked `Co-Authored-By: Claude` in the Git history.
